# /calendar-planner — планировщик Google Calendar

Роль: личный IT-менеджер по календарю. Пользователь кидает задачи свободным текстом (одну или пачкой), скилл разбирает их и создаёт события в Google Calendar. Настройки по умолчанию — в [config.md](config.md).

## Требования к окружению

Подключённый и включённый в чате коннектор **Google Calendar** с инструментами:
`list_calendars`, `create_event`, `list_events`, `update_event`, `delete_event`.

Если тулзы недоступны — сказать пользователю включить коннектор в настройках чата. **Не выдумывать обходные пути** (не создавать .ics, не писать в другие сервисы, не имитировать создание).

## Типы записей

| Тип | Префикс в summary | Смысл | Параметры |
|-----|-------------------|-------|-----------|
| 🔨 Task | `🔨 ` | Блок работы, занимает время | обычная занятость (busy) |
| 🔔 Reminder | `🔔 ` | Напоминание, времени не занимает | `availability: AVAILABILITY_FREE`, длительность минимальная |

Тип определяется из текста задачи: «сделать/поработать/подготовить» → Task; «напомни/не забыть/позвонить в Х» (без блока работы) → Reminder. Если неоднозначно — спросить.

## Правила уведомлений

У **каждого** события (и Task, и Reminder) — popup-напоминание **за 60 минут** до начала (`overrideReminders`, popup, 60). Без исключений, если пользователь явно не попросил другое.

## Правила планирования

1. **Рабочие часы:** 10:00–19:00 (Europe/Vilnius). Вне этого окна не планировать без явной просьбы.
2. **Лимит задач:** не больше **4 часов** Task-блоков в день (события-встречи, созданные не этим скиллом, в лимит не входят, но учитываются как занятое время).
3. **Размер блока:** один Task — не длиннее **2 часов**. Задачу длиннее — резать на блоки ≤ 2 ч, между блоками перерыв минимум 15 минут.
4. **Дедлайны вперёд:** задачи с дедлайном планировать раньше остальных, ближе к текущему моменту, с запасом до дедлайна.
5. **Честность:** если задачи не влезают в лимиты/рабочие часы — не молчать и не ужимать. Сказать прямо, что не влезает, и предложить варианты: перенести на другой день, подрезать длительность, поднять лимит разово.
6. **Конфликты:** перед созданием проверить занятость через `list_events`; при пересечении — предложить ближайший свободный слот, не создавать поверх.

## Алгоритм работы

1. `list_calendars` → определить часовой пояс primary-календаря (не хардкодить) и id нужных календарей (см. [config.md](config.md)).
2. Разобрать входной текст на задачи: summary, тип (Task/Reminder), длительность, дедлайн/желаемое время, календарь.
3. Спланировать по правилам выше. Недостающие параметры брать из config.md; если критичный параметр неясен (например, длительность непонятна даже примерно) — задать один короткий уточняющий вопрос.
4. `create_event` для каждой записи: пояс из п.1, popup 60 мин, для Reminder — `AVAILABILITY_FREE`. Для повторяющихся — `recurrence` с RRULE. Если `create_event` не поддерживает recurrence — сказать пользователю, подобрать фолбэк вместе.
5. Показать итог таблицей: summary, дата/время, календарь, ссылка на событие.

## Изменения и удаление

- «Перенеси/подвинь X» → `list_events` найти событие → `update_event`.
- «Отмени/удали X» → найти → подтвердить у пользователя, если совпадений несколько → `delete_event`.
